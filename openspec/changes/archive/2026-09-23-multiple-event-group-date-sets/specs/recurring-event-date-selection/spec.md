## MODIFIED Requirements

### Requirement: Administrator can create a single event by default

The system SHALL open the event-date control with one date set, weekly recurrence disabled, and the one-off date and time fields available without requiring an end date. The administrator SHALL be able to add additional independent date sets without changing the existing set.

#### Scenario: One-off mode is displayed by default
- **WHEN** an administrator opens an event-group creation form
- **THEN** one date set is displayed, recurrence is disabled, and the one-off date and time fields are available without requiring an end date

#### Scenario: Administrator adds another date set
- **WHEN** an administrator adds a date set
- **THEN** a new independent date set is displayed and the values and generated occurrences of existing date sets remain unchanged

#### Scenario: Single event is submitted
- **WHEN** an administrator submits a valid form containing one date set with recurrence disabled
- **THEN** the existing event-group workflow receives exactly one concrete `from` and `to` pair

### Requirement: Administrator can toggle weekly recurrence

The system SHALL provide a clearly labelled control in every date set that enables or disables weekly recurrence without changing that set's existing event details or time range.

#### Scenario: Recurrence is enabled
- **WHEN** an administrator enables weekly recurrence in a date set
- **THEN** that set displays the inclusive recurrence end date and generated occurrence controls

#### Scenario: Recurrence is disabled after being enabled
- **WHEN** an administrator disables weekly recurrence in a date set
- **THEN** that set returns to one-off mode and contributes only its first date and configured time range

#### Scenario: One date set changes independently
- **WHEN** an administrator changes recurrence or date values in one date set
- **THEN** occurrences from other date sets remain unchanged

### Requirement: Administrator can define independent weekly schedules

When weekly recurrence is enabled, each date set SHALL allow an administrator to provide its own first meeting date, meeting start time, meeting end time, and inclusive schedule end date. Each set SHALL generate occurrences on the weekday of its own first meeting date at weekly intervals through its own inclusive end date.

#### Scenario: Multiple weekly schedules are defined
- **WHEN** an administrator defines two valid weekly date sets with different first meeting weekdays
- **THEN** the system generates occurrences for both weekdays according to each set's own date range and time range

#### Scenario: Schedule uses one fixed time range
- **WHEN** an administrator provides valid start and end times for a date set
- **THEN** every occurrence generated by that set has the same local start and end times

### Requirement: Administrator can exclude individual weeks

The system SHALL allow an administrator to exclude any generated weekly occurrence within each date set before submitting the schedule.

#### Scenario: Week is skipped in one set
- **WHEN** an administrator marks a generated occurrence in one date set as skipped
- **THEN** that occurrence is omitted while occurrences from the same set and all other date sets remain eligible for submission

#### Scenario: No weeks are skipped
- **WHEN** an administrator submits a schedule without excluding an occurrence from any date set
- **THEN** every generated occurrence from every date set is included in the concrete instance list

### Requirement: Schedule preview reflects submitted occurrences

The system SHALL display generated occurrences and the count of occurrences that will be submitted for each date set and for the combined schedule.

#### Scenario: Preview updates after exclusion
- **WHEN** an administrator excludes or restores a generated occurrence
- **THEN** that date set's preview, its count, and the combined occurrence count update to reflect only occurrences that will be submitted

#### Scenario: Date set is removed
- **WHEN** an administrator removes a date set
- **THEN** its occurrences are removed from the combined preview and submission count while all remaining date sets are unchanged

### Requirement: Invalid schedules cannot be submitted

The system SHALL prevent submission when any date set has an invalid date, invalid time range, invalid recurrence date range, no remaining occurrences, or an exact duplicate occurrence with another date set.

#### Scenario: End date precedes first date
- **WHEN** weekly recurrence is enabled in a date set and its end date precedes its first meeting date
- **THEN** the system displays a validation error and does not submit instances

#### Scenario: End time is not after start time
- **WHEN** a date set has an end time equal to or earlier than its start time
- **THEN** the system displays a validation error and does not submit instances

#### Scenario: All generated weeks are skipped in one set
- **WHEN** an administrator excludes every generated occurrence in a date set
- **THEN** the system displays a validation error for that date set and does not submit an empty contribution from it

#### Scenario: One-off date or time is incomplete
- **WHEN** weekly recurrence is disabled and a date set has not provided a date or valid start/end times
- **THEN** the system displays a validation error and does not submit instances

#### Scenario: Date sets contain duplicate exact occurrences
- **WHEN** two date sets generate the same `from` and `to` values
- **THEN** the system displays a duplicate-occurrence validation error and does not submit the schedule until the duplicate is removed

### Requirement: Submitted occurrences preserve local meeting times

The system SHALL generate each occurrence in every date set from its calendar date and configured local time so that weekly meetings retain their configured wall-clock time across daylight-saving transitions.

#### Scenario: Weekly schedule crosses a daylight-saving transition
- **WHEN** any weekly date set spans a daylight-saving transition
- **THEN** each occurrence represents that set's configured local start and end times on its generated calendar date

### Requirement: Existing booking workflows receive concrete instances

The system SHALL submit all remaining occurrences from all date sets as one flattened `instances` payload using the existing concrete `from` and `to` pair format consumed by event-group creation.

#### Scenario: Multiple date sets are submitted successfully
- **WHEN** an administrator submits a valid form with multiple date sets and one or more remaining occurrences in each set
- **THEN** the existing event-group workflow receives one concrete `from` and `to` pair for each remaining occurrence across all date sets

#### Scenario: Monthly recurrence is not offered
- **WHEN** an administrator configures event-group dates
- **THEN** the date controls offer one-off and weekly recurrence only and do not offer monthly recurrence
